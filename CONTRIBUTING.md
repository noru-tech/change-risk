# Contributing

Thanks for helping. Bugs, signal adapters and specification changes are all welcome; open an issue
first for anything that changes how a tier is derived.

## Ground rules

- **Deterministic.** `evaluate` never reads the network, the clock, the environment or `git`. The
  same facts give the same bytes.
- **The base revision rule is not negotiable.** The map and the policy come from the target branch.
  Nothing a change contains may lower the requirements it is held to.
- **No content analysis and no model** in the derivation.
- **Every derivation change comes with a conformance vector**, and its `expected` is reviewed, not
  only regenerated.
- **Minimal dependencies**, pure Rust.

## Layout

| Path | What |
| --- | --- |
| `spec/change-risk.md` | The specification |
| `schemas/` | JSON Schemas, embedded in the binary |
| `src/evaluate.rs` | The derivation |
| `src/collect/` | git, GitHub and GitLab |
| `src/signals.rs` | Signal adapters |
| `src/output.rs`, `src/compile.rs`, `src/population.rs` | Outputs |
| `conformance/` | The corpus and its runner |
| `action.yml`, `templates/` | GitHub Action and GitLab component |

## Checks

```bash
cargo fmt --all
cargo clippy --all-targets --all-features -- -D warnings
cargo test
python3 conformance/run.py --verifier "target/debug/crisk -q evaluate -f json"
```

`UPDATE_CORPUS=1 cargo test --test conformance` regenerates the corpus expectations, and
`UPDATE_ASSETS=1 cargo test --test assets` the committed completions and man pages.

## Releases

Tag `vX.Y.Z` on `main`; `release.yml` (generated by cargo-dist) builds, attests and publishes.
